# AiFi Talk website

Read `DESIGN-SYSTEM.md` before changing UI. Use `tokens.css` for shared color and font choices; `style.css` contains the implemented component patterns. Preserve the warm editorial direction and bilingual behavior.

Keep social destinations in the single `socials` registry in `i18n.js`. Reuse stable story IDs across translations and saved state. The website is deployed at https://aifi-talk.vercel.app from the selected files in the aifi-talk GitHub repository. Use RELEASE.md for build and deployment instructions. Publish only explicitly selected public article copies; newsletter/video services are not connected.

Define observable acceptance criteria before behavior changes. Verify the affected desktop/mobile and keyboard/touch journey, both languages, and relevant reload persistence. Save expected/observed evidence under `evidence/` and report PASS, FAIL, or NOT TESTED. Existing probes assume port 4328.


## Icon-first controls
Prefer recognizable icons over visible text for social destinations and familiar utility actions. Use local Simple Icons brand SVGs and consistent 24px outline utility icons from `assets/icons/`. Keep accessible names, localized hover titles, visible keyboard focus, and at least 44px touch targets. Native language names and editorial navigation retain text where icons would obscure meaning. Social links use one registry; do not repeat handles throughout the UI. Icon source attribution is in `assets/icons/SOURCES.md`.

## Public assets and design standards
`/assets/` is the public brand-assets and design-standards page, generated by `scripts/assets-page.mjs` from `DESIGN-SYSTEM.md`. Every design change must update the affected rules in `DESIGN-SYSTEM.md` in the same change. Keep approved logo downloads and previews current, reuse actual CSS tokens, and verify this page with the changed UI before release. Do not maintain a separate manual copy of the public standards.
